# 通用 phonecontrol 控制规则

## 触发条件

只要当前任务准备调用任意 `phonecontrol` MCP 工具，就先加载本参考文件。它适用于闲鱼、抖音、微信、浏览器、相册和其他手机应用。

## 核心目标

把每次手机操作沉淀为两层知识：

1. **通用经验**：跨应用、跨任务仍然成立的控制器动作，例如打开双开应用时默认选择第二个实例、页面切换后重新读取节点、输入框快速注入文字。
2. **专用经验**：只对某个应用或某个任务成立的业务规则，例如目标评论关键词、闲鱼商品价格字段、某页面的发布按钮。

不要把专用坐标、应用包名、业务关键词直接提升为通用经验。

## 每次 phonecontrol 任务的固定顺序

1. 为任务生成稳定的 `task_id`，格式建议为 `<app>_<action>_<date>`。
2. 读取当前工作区 `.xianyusj/phonecontrol_memory.md`：先查精确任务 SOP，再查相似任务，最后查通用动作卡。
3. 如果没有精确任务 SOP，先创建一个“草稿 SOP”，不要假装已有经验。
4. 在第一个 phonecontrol 工具调用前记录任务和动作的开始时间。
5. 每完成一个动作，记录成功信号、结束时间、耗时、方法和重试次数。
6. 失败时先记录失败，不连续盲点；根据动作卡的恢复策略切换方法。
7. 任务结束后，把新经验放入“待分类区”，再判断它是通用经验还是专用经验。
8. 只有满足晋升条件的经验才能进入通用动作卡。

## 知识分类规则

### 判断为通用经验

满足以下条件之一即可作为候选，但至少经过两个不同任务或应用验证后，才能标记为“已晋升”：

- 动作目的相同，和具体业务内容无关；
- 只依赖手机系统、phonecontrol 能力或稳定的 UI 语义；
- 成功信号和失败恢复在多个应用中相同；
- 不包含具体商品、评论、账号、关键词或业务字段。

示例：

```text
动作：打开双开应用
通用默认：优先选择第二个实例
通用成功信号：进入目标应用，且实例序号/窗口标识为第二个
恢复：重新读取当前实例节点，不复用旧 node_id
```

### 判断为专用经验

出现以下内容时，默认保留在任务 SOP 或应用适配器中：

- 应用包名、具体页面名称或业务字段；
- 特定关键词、商品标题、评论内容或账号对象；
- 只在某个应用出现的按钮、页面顺序或坐标；
- 业务判断，例如“找到包含某句话的评论后点赞”。

### 经验晋升

```text
任务中新发现 → 待分类 → 跨第二个任务复用 → 已验证公共动作
```

如果第二个任务验证失败，不删除原记录，而是降级为“应用适配器”或标记为“待验证”。

## 跨应用示例

任务：`douyin_like_comments`

```text
1. 打开抖音第二个实例        → 公共动作 open_dual_instance
2. 进入目标视频              → 抖音专用步骤
3. 识别评论区                → 公共候选 locate_comments_area
4. 找到包含指定内容的评论     → 专用经验 match_comment_text
5. 点击点赞                  → 公共候选 like_content
6. 检查点赞状态              → 公共候选 verify_liked_state
```

这里“识别评论区的位置”可以在多个内容应用中验证后晋升为通用动作；“评论特定内容”始终属于该任务的专用经验。

## 任务 SOP 的最小结构

每个任务只需要记录以下内容：

```text
任务名称
应用/目标
当前状态
前置条件
步骤清单
调用的公共动作卡
专用经验
成功信号
失败恢复
最近一次耗时
```

## 安全与边界

- 不记录密码、验证码、Bearer Token、Cookie 或完整个人数据。
- 只记录完成动作所需的最小页面事实。
- 外部写操作仍需按照用户当前请求执行；本参考只负责记忆、计时和流程改良，不扩大授权。
- 没有计时数据时必须明确写入 `timing_status=missing`，不能伪造耗时。
